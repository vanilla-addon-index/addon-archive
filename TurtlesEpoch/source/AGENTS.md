# TurtleTongue

AI-generated voice lines for NPC quest text, books, and world objects in Turtle WoW (1.12). Race-specific voice cloning via Fish Speech S2 Pro. Full VanillaStoryline-style frame replacement UI with 3D portraits and voice playback. Pure plug-and-play addon — pre-generated voices distributed as release download.

**Current Status (v1.1.1): Released. 18,391 `.ogg` voice clips with matching `voice_manifest.lua`. Quest resolution uses a text-signature candidate resolver so same-title quest chains and multi-giver quests disambiguate correctly via per-NPC path buckets. `.ogg` files re-encoded through libvorbis at `-q:a 2` for cross-platform playback (notably WINE) — lower bitrate is empirically required to avoid non-monotonic granulepos in the Vorbis stream. Per-NPC greeting mute toggle in Settings.**

## Technical Constraints (1.12 / Turtle WoW)

### Critical API Constraints
- **No file I/O**: `AppendToFile`, `ReadFile`, `WriteFile`, `DeleteFile` ALL DISABLED in Turtle WoW
- **No HTTP from Lua**: Cannot call external services from addon code
- **SavedVariables flush on /reload or logout only**: Settings persist via standard SavedVariables
- **PlaySoundFile() works for post-load files**: .wav files added to disk AFTER addon loads CAN be played without /reload
- **No StopSoundFile()**: Use CVar toggle hack (`MasterSoundEffects` 0→1) to stop audio
- **UnitRace("npc")**: Returns `nil` for non-playable races (ogres, centaurs, etc.)
- **UnitSex("npc")**: Returns 1=unknown, 2=male, 3=female in Turtle WoW
- **No UnitGUID**: Added in 2.4, not available in 1.12

### 1.12 Lua Quirks
- No `%` modulo operator → use `math.mod(a, b)`
- No `//` floor division → use `math.floor(a / b)`
- No `SetSize()` → use `SetWidth()` + `SetHeight()`
- No `SetColorTexture()` → use `SetTexture(r, g, b)` for solid colors
- Use `this` in script handlers, not `self`
- Use `event`, `arg1`, `arg2` globals for event arguments
- `SetPoint`: must specify all 5 args: `frame:SetPoint("CENTER", parent, "CENTER", x, y)`
- 0.1s delay needed after quest/gossip events before text APIs are populated
- **`string.match` does not exist** — use global functions: `strfind`, `strsub`, `strlower`, `strlen`. The `string.*` table methods are not exposed in 1.12.
- **`strgsub` does not exist** — use `string.gsub` (standard Lua 5.0 base library, available in 1.12). WoW shorthand globals: `strfind`, `strsub`, `strlower`, `strlen`, `strupper`, `strbyte`, `strrep` — that's it.

### Addon Conventions
- **TOC**: `Interface: 11200`, `## SavedVariables: TurtleTongueDB`
- **TOC file paths**: Use backslashes (`data\npc_data.lua`)
- **Sound format**: .wav files
- **Portrait format**: .tga, 256x256, 24-bit RGB
- **Minimap icon**: 32x32 RGBA TGA format

## NPC Detection Strategy

### The Problem
`UnitRace("npc")` only returns values for playable races. The client does not expose DisplayID or NPC entry ID at runtime.

### The Solution: Pre-built NPC Database
Name → race lookup table built by crawling Turtle WoW database and mapping DisplayID → Race using DBC files.

### DBC Data Flow

```
DisplayID (from website)
    ↓
CreatureDisplayInfo.csv → ModelID + ExtendedDisplayInfoID
    ↓
If ExtendedDisplayInfoID > 0:
    CreatureDisplayInfoExtra.csv → DisplayRaceID + DisplaySexID
    ChrRaces.csv → Race Name
Else (ExtendedDisplayInfoID = 0):
    CreatureModelData.csv → Model Name → Creature Type
```

**Sex from DBC**: `CreatureDisplayInfoExtra.csv` col 2 = DisplaySexID (0=male, 1=female). Available for all humanoid NPCs without re-crawling.

**Example - Fleet Master Seahorn (DisplayID 1667):**
1. CreatureDisplayInfo: 1667 → ExtendedDisplayInfoID 382
2. CreatureDisplayInfoExtra: 382 → DisplayRaceID 6, DisplaySexID 0 (male)
3. ChrRaces: 6 → Tauren ✓

## Quest Text Extraction

### Events to Hook
| Event | Text API | Dialog Type |
|-------|----------|-------------|
| `QUEST_DETAIL` | `GetQuestText()` + `GetTitleText()` | quest_detail |
| `QUEST_PROGRESS` | `GetProgressText()` + `GetTitleText()` | quest_progress |
| `QUEST_COMPLETE` | `GetRewardText()` + `GetTitleText()` | quest_complete |
| `QUEST_GREETING` | `GetGreetingText()` | quest_greeting |
| `GOSSIP_SHOW` | `GetGossipText()` | gossip (manual entries only) |
| `ITEM_TEXT_BEGIN` | (reset page counter) | — |
| `ITEM_TEXT_READY` | `ItemTextGetText()` + `ItemTextTitleText:GetText()` | book (per page) |

**Book page tracking**: `ITEM_TEXT_BEGIN` resets a page counter to 1. Each `ITEM_TEXT_READY` uses the current page counter, then increments on `ItemTextNextPage()`. This gives us title + page number — no text hashing needed.

### Data Pre-Crawled from database.turtlecraft.gg
- Quest text: `/?quest={id}` → Description, Progress, Completion + quest giver NPC name
- Book/object text: `/?object={id}` → Content text (books, plaques, signs)

### Data Added Manually (from user bug reports)
- Quest greeting text (multi-quest NPC intro)
- Inventory items (notes, letters — only visible in-game) → **narrator voice**
- Notable gossip conversations with lore significance → **NPC race/sex voice** (looked up from npc_database)
- Custom Turtle WoW content not in database

### Voice Assignment for Manual Entry Types
- **Gossip**: NPC-spoken → race/sex from `npc_database.json` (or explicit `--race`/`--sex` override)
- **Item text**: Player reads object → narrator voice (same as books/objects)
- **Quest greeting**: NPC-spoken → race/sex from `npc_database.json`

### Voice File Matching Strategy

**Problem**: Crawled text and in-game API text can differ (whitespace, HTML entities, `$N` vs `<name>`, paragraph breaks). Hashing full text is fragile.

**Solution**: Key on short, stable metadata — not the text body.

| Source | Runtime Key | Crawl Key | Hash Input |
|--------|------------|-----------|------------|
| **Quests** | `GetTitleText()` + dialog type | `title` + field name | quest title (short, clean, no subs) |
| **Books** | `ItemTextTitleText:GetText()` + page number | `name` + page index from crawl | book title + page number |
| **Gossip (manual)** | `UnitName("npc")` + text | curated text | normalized text (we control both sides) |
| **Item text (manual)** | `ItemTextTitleText:GetText()` + page number | curated text | item title + page number |

**Quest matching**: Quest titles are short, stable, free of player substitutions (`$N`/`$C`/`$R`), and identical between the website and `GetTitleText()`. For the rare duplicate quest titles, the NPC name (in the file path) disambiguates.

**Inventory-item-triggered quests**: Some quests are started by right-clicking an inventory item (notes, writs, letters) rather than talking to an NPC. The game still fires `QUEST_DETAIL`, but `UnitName("npc")` returns `nil` (no NPC is targeted). `BuildSoundPath` therefore uses `"unknown"` as the NPC directory and the predicted path won't match the manifest.

**Resolution via manifest hash index**: `BuildQuestDetailHashIndex()` runs at `ADDON_LOADED` and scans every path in `TT_VOICE_MANIFEST` that contains `quest_detail_`. It extracts the 8-char DJB2 hash from each path (e.g. `sounds\orc\gornek\quest_detail_a1b2c3d4.wav` → `a1b2c3d4`) and builds `QUEST_DETAIL_HASH_INDEX[hash] = fullPath`. When the normal predicted path fails a manifest lookup, `OnDialogText` falls back to `ResolveQuestDetailByManifestHash(title)`, which hashes the quest title and looks up the result in that index. Because the title hash is globally unique across all NPCs, the correct file is found regardless of which NPC subdirectory it lives in.

**Text-signature resolver (v1.1)**: For dialog types where the quest-ID-based hash key is unreliable (`GetQuestID()` returns 0 for inventory-item-triggered quests, and same-title chains collide), `generate_voice.py` writes per-dialog-type tables `TT_QUEST_DETAIL_BY_TEXTSIG` / `_PROGRESS_ / `_COMPLETE_ / `_GREETING_` keyed on a normalized text signature of the dialog body. At runtime, `BuildTextSigCandidates(text)` produces up to 4 candidate keys per dialog text — raw, +race substitution, +class substitution, both — because we can't tell from runtime text alone whether words like "human" came from `<race>` tokens or were plain nouns. The first candidate that hits the manifest wins. Player NAME is always replaced with the literal token `"name"` on both the generation and runtime sides. `$Gmale:female;` is hardcoded to the male form at generation time. Multi-giver quests (war effort etc.) store a list of paths per signature, disambiguated at lookup time by `PickPathByNPC(entry, npcName)` matching the NPC folder.

**Book matching**: `ItemTextTitleText:GetText()` returns the book/object title (matches `name` from crawl). Page number tracked via `ITEM_TEXT_BEGIN` (reset) + `ITEM_TEXT_READY` (increment). Each page gets its own voice file: `book_p1_{hash}.wav`, `book_p2_{hash}.wav`, etc. Hash input = `title_pageN`. No text body comparison needed.

**Gossip matching**: Manual entries only — we write both the entry and generate the voice, so text is identical by definition. Runtime: `UnitName("npc")` + aggressive text normalization (lowercase, strip whitespace/punctuation) + first 8 chars of MD5. If an NPC has only one gossip entry, NPC name alone suffices.

**Item text matching**: Manual entries for inventory items (notes, letters). Same `ITEM_TEXT_BEGIN`/`ITEM_TEXT_READY` event flow as books — title + page number key, narrator voice. Multi-page items get `item_p1_`, `item_p2_`, etc.

### Predicted Path Convention
`Interface\AddOns\TurtleTongue\sounds\{race}\{npc_name_normalized}\{dialog_type}_{key_hash}.wav`

Examples:
- Quest: `sounds\orc\gornek\quest_detail_a1b2c3d4.wav` (hash of "Cutting Teeth")
- Book page 1: `sounds\narrator\the_emerald_dream\book_p1_f7e8d9c0.wav` (hash of "The Emerald Dream_page1")
- Book page 2: `sounds\narrator\the_emerald_dream\book_p2_b3a4c5d6.wav` (hash of "The Emerald Dream_page2")
- Gossip: `sounds\human\guard_thomas\gossip_e1f2a3b4.wav` (hash of normalized text)

Where:
- `race` = lowercase normalized race (e.g., "orc", "human", "narrator")
- `npc_name_normalized` = lowercase, spaces→underscores, stripped special chars (for books: book title normalized)
- `dialog_type` = quest_detail, quest_progress, quest_complete, quest_greeting, gossip, book_pN, item_pN
- `key_hash` = first 8 hex chars of DJB2 hash of the **key** (quest title for quests, title+pageN for books/items, normalized text for gossip)

## UI Design (VanillaStoryline-Style Full Replacement)

### Frame Architecture
- Invisible event frame (for event handling only)
- `TurtleTongueQueueFrame` (named, parented to UIParent)
  - `UI-DialogBox-Background` + `UI-DialogBox-Border` backdrop (300×130)
  - `UIPanelCloseButton` at TOPRIGHT (standard WoW X button)
  - Left column (8..70px): 3D PlayerModel portrait (62×62) OR 2D icon texture for narrator/books
  - Title FontString (`GameFontHighlight`): `TOP` anchor centered on frame, `SetWidth(200)`
  - NPC name FontString (`GameFontNormalSmall`): below title, same centering, blank for narrator entries
  - "Skip" + "Clear Queue" `UIPanelButtonTemplate` buttons at BOTTOMRIGHT
  - Draggable: `SetMovable(true)` + `RegisterForDrag("LeftButton")`, saves `{point, relPoint, x, y}` to `TurtleTongueDB.windowPos`
  - Position restored from `TurtleTongueDB.windowPos` on frame creation; default `TOP, UIParent, TOP, 0, -120`
- `TurtleTongueSettingsFrame` (named, in UISpecialFrames for ESC close)
  - 660×560, three-column checkbox layout

### 3D Portrait
- `CreateFrame("PlayerModel", nil, parent)` set to 62×62, `LEFT` anchor at x=8 vertically centered
- `SetUnit("npc")` + `SetCamera(0)` when a live NPC is present
- Portrait latched after NPC dialog closes (`hasPortraitSnapshot` flag) so it persists during playback
- **3D models overflow their declared frame bounds vertically.** All text (title, NPC name) is therefore anchored to the frame's TOP center — NOT below the portrait — to avoid overlap
- 2D icon fallback: `INV_Misc_Book_09` for narrator/book entries; `AvailableQuestIcon` / `ActiveQuestIcon` when no portrait is available
- `PlayerModel` pool: created once, reused across entries to avoid per-entry frame churn

### Layout Notes
- Two-column design: portrait occupies x=8..70 (left 82px), all text starts at frame center (SetWidth=200 centered on full 300px frame)
- `UIPanelCloseButton` template provides standard X button at TOPRIGHT with built-in texture and click behavior

### Quest Log Replay
- `QuestLogButton.lua` was not implemented. Queue UI replaces it: once an event fires, audio plays immediately from the queue. `/tt show` re-opens the frame if dismissed.

### Fish Speech Server Tuning

#### `--compile` Flag (torch.compile)
The `--compile` flag on `api_server.py` enables `torch.compile()` which fuses CUDA kernels for the transformer and attention layers. Effects:
- **First request**: ~60-90s slower (compilation + warm-up)
- **Subsequent requests**: 2-4x faster decode (~30 tok/s vs ~10 tok/s without)
- **VRAM**: No significant extra usage — compiled kernels replace interpreted ones
- Always use `--compile` for batch generation. Only skip it for quick one-off debugging.

#### KV Cache Patch (VRAM Optimization)
Fish Speech S2 Pro defaults to a 32,768-token KV cache, which allocates ~4.8 GB VRAM. We patch this down to 4,096 tokens in **3 sites** in:

`fish-speech/fish_speech/models/text2semantic/inference.py`:
```python
# Line ~282 (generate_long function)
kv_limit = min(model.config.max_seq_len, 4096)

# Line ~765 (launch_thread_safe_queue worker)
kv_seq_len = min(model.config.max_seq_len, 4096)

# Line ~888 (inference_worker_v2)
max_seq_len=min(model.config.max_seq_len, 4096),
```

All three `setup_caches()` call sites must be patched — if only one is changed, the other code paths will still allocate the full 32K cache and OOM.

This saves ~4.2 GB VRAM (4.8 GB → 0.6 GB for cache). The 4,096 cap is safe because our worst-case generation uses ~3,016 tokens total:
- 45s reference audio ≈ 968 tokens (audio encodes at ~21.5 tokens/sec)
- max_new_tokens = 2048 (longest output ~95s speech)
- Total: ~3,016 tokens — well under the 4,096 cap

Without this patch, generation will OOM on 24 GB GPUs under heavy reference loading.

#### Reference Audio Parameters
`_build_references()` in `generate_voice.py` controls how much reference audio is sent to the model:

| Parameter | Default | Description |
|-----------|---------|-------------|
| `max_duration` | 45.0s | Total reference audio budget across all clips |
| `per_clip_max` | 10.0s | Max seconds used from each individual clip (center-cropped) |

**Quality vs speed tradeoffs:**
- More reference audio → better voice cloning fidelity (timbre, cadence, prosody)
- Diminishing returns beyond ~45-60s total
- Longer `per_clip_max` gives the model more prosodic context per sample (full sentences vs fragments)
- More reference increases **prefill** time (encoding all reference tokens before generation starts) but barely affects **decode** speed
- Practical impact: 60s ref is ~10-20% slower per line than 30s ref, but noticeably better cloning

**Token budget math:**
```
Reference audio: ~21.5 tokens per second of audio
45s reference        ≈   968 tokens (prefill)
max_new_tokens=2048  ≈ 2,048 tokens (decode — longest output ~95s speech)
Total                ≈ 3,016 tokens — fits in 4,096 KV cache with 26% headroom
```

#### PYTORCH_CUDA_ALLOC_CONF
The `expandable_segments:True` setting prevents VRAM fragmentation on 24 GB GPUs. Without it, PyTorch's default allocator can fragment memory after many sequential generations, eventually causing OOM even with free VRAM available.

### Per-NPC Voice Uniqueness
Every NPC should sound distinct even when sharing the same race/sex profile. A male Orc quest giver in Durotar should not sound identical to a male Orc quest giver in Orgrimmar — they inherit the same "Orc-ish" qualities but have their own voice.

**How it works:**
- Each NPC gets a **deterministic seed** derived from their name (DJB2 hash). This seed controls:
  - Which subset/combination of the race's reference clips are used
  - The generation temperature (slight variation within a controlled range)
- Same NPC name → same seed → same voice characteristics on every generation run
- Different NPC names → different seeds → different voices, all within the race's tonal range

### Voice Anchor (Cross-Line Consistency)
Once an NPC's first line is generated, all subsequent lines must sound like the same character. An NPC cannot sound one way during quest_detail and totally different during quest_complete.

**How it works:**
- **First line generated for an NPC**: Uses race samples + NPC-specific seed → produces output `.wav`
- **Voice anchor saved**: The first output is copied to `sounds/{race}/{npc}/.voice_anchor.wav`
- **All subsequent lines**: Use `.voice_anchor.wav` as the reference instead of the original race samples
- Result: Every line from that NPC sounds like the same person

**Generation flow example:**
```
NPC "Gornek" (Orc, male) — 3 dialog lines

Line 1: ref = samples/orc_male/*.wav + seed("Gornek")
  → generates quest_detail_a1b2c3d4.wav
  → saves copy as sounds/orc/gornek/.voice_anchor.wav

Line 2: ref = sounds/orc/gornek/.voice_anchor.wav
  → generates quest_progress_e5f6a7b8.wav (same voice as line 1)

Line 3: ref = sounds/orc/gornek/.voice_anchor.wav
  → generates quest_complete_c9d0e1f2.wav (same voice as line 1)
```

**Regeneration**: `--force` flag deletes the voice anchor too, so the NPC gets a fresh voice from race samples. Without `--force`, existing anchors are reused (incremental generation stays consistent).

**Tier 3 named NPCs**: Skip the seed variation — they use their dedicated `samples/custom/{npc}/` clips directly as the voice anchor. Thrall always sounds like the Thrall samples, not a random Orc variation.

### Voice Selection Logic

2. Check npc_database race+sex → `samples/{race}_{sex}/` profile (base races)
3. For creature types → `samples/creature/{type}/` or `samples/creature/{type}_{sex}/` (centaur/naga)
4. Fallback → `samples/narrator/`

### Voice Post-Processing (`scripts/audio_effects.py`)
Donor voice + post-processing system driven by per-profile JSON configs in `data/voice_configs/`.

**Problem 1: Extreme pitch samples**
Some game audio samples have extreme fundamental frequencies that may challenge the TTS model. Donor voice routing resolves this.

**Solution: Donor voice + pitch shift**
Profiles with extreme-F0 samples specify a `donor_voice` — a clean human voice sample set. The TTS generates using the donor's samples, producing clean natural speech. Post-processing then pitch-shifts + applies effects to transform the output into the target character voice.

**Problem 2: Game-audio DSP not preserved**
WC3/WoW samples for creatures (furbolgs, elementals, keepers, etc.) have heavy effects (reverb, echo, guttural processing) that the TTS model cannot clone — it only reproduces speech patterns and bare timbre.

**Solution: Post-generation effects**
Apply per-profile DSP effects (reverb, EQ, pitch shift) to TTS output.

**Voice config JSON schema** (`data/voice_configs/{profile}.json`):
```json
{
  "donor_voice": null,          // or sample dir relative to samples/, e.g. "human_female"
  "pitch_shift": 0,             // semitones to shift TTS output
  "reverb": 0.0,                // wet mix ratio 0.0-1.0
  "reverb_decay": 0.6,          // reverb tail in seconds
  "bass_boost_db": 0,           // low-shelf gain below 250 Hz
  "treble_boost_db": 0,         // high-shelf gain above 4000 Hz
  "saturation": 0.0,            // harmonic saturation 0.0-1.0 (gritty/raspy via tanh soft clipping)
  "speed": 1.0,                 // playback speed 0.7-1.3 (1.0 = normal, <1 = slower)
  "status": "untested",         // untested / testing / approved
  "test_quest_id": null,        // quick test regeneration
  "notes": ""                   // human notes about tuning decisions
}
```

- `AcquirePortraitModel()` / `ReleasePortraitModel()` — models created once and reused
- Off-screen at (10000, 10000) when pooled to keep them alive without being visible

- `hasPortraitSnapshot` flag prevents re-binding after the dialog closes, keeping the portrait alive during playback

1. If narrator/book/item entry → hide portrait3D, show 2D book icon (`INV_Misc_Book_09`)

### EventHandler — Manifest Hash Resolver (COMPLETE)
The central matching improvement enabling inventory-item-triggered quests.

**Problem**: Some quests fire `QUEST_DETAIL` when a player right-clicks an inventory item (writs, letters, notes). No NPC is targeted at that moment — `UnitName("npc")` returns `nil`. `BuildSoundPath` uses `"unknown"` as the NPC subdirectory. The resulting predicted path does not exist in the manifest, which has the true quest giver's name in the path.

**Solution: Manifest hash index**

`BuildQuestDetailHashIndex()` runs once at `ADDON_LOADED`:
```lua
-- Scans TT_VOICE_MANIFEST for all quest_detail_ paths
-- Extracts 8-char hash from each: sounds\orc\gornek\quest_detail_a1b2c3d4.wav → "a1b2c3d4"
-- Builds: QUEST_DETAIL_HASH_INDEX["a1b2c3d4"] = "sounds\orc\gornek\quest_detail_a1b2c3d4.wav"
```

`ResolveQuestDetailByManifestHash(title)`:
```lua
-- Hash the quest title: strlower(TT:HashKey(title))
-- Look up in QUEST_DETAIL_HASH_INDEX
-- Return the full manifest path, or nil if not found
```

`OnDialogText` flow for `quest_detail`:
1. Build predicted path (`BuildSoundPath(race, npcName, "quest_detail", title)`)
2. Check manifest: if found → use it
3. If NOT found → call `ResolveQuestDetailByManifestHash(title)`
4. If that returns a path → use it (inventory-item quest matched)
5. If still nothing → `Debug("No voice file in manifest")` and return silently

**Why the hash is globally unique**: The DJB2 hash of the quest title produces the same 8-char hex regardless of which NPC directory the file lives in. Quest titles don't contain `$N`/player markers, so they're identical between the website crawl and `GetTitleText()` at runtime.

**String function note**: 1.12 does not expose `string.match` or `strgsub`. Use WoW's global shortcuts for search/extract: `strfind(s, pat)`, `strsub(s, i, j)`, `strlower(s)`, `strlen(s)`, `strupper(s)`. For replacement, use `string.gsub(s, pat, rep)` — it's a standard Lua 5.0 base function that IS available. `string.format` / `string.len` / `string.byte` / `string.lower` / `string.gsub` all work because they're base library functions, not string metamethods.

## Decisions Log

| Decision | Choice | Rationale |
|----------|--------|-----------|
| TTS Engine | Fish Speech S2 Pro | Voice cloning from reference samples, local GPU, HTTP API server |
| UI Style | Full VanillaStoryline-style frame replacement | Immersive experience with 3D portraits |
| Scope | Quest text + books/objects + curated manual entries | High-quality coverage of meaningful dialog |
| Distribution | Pre-generated voices as Codeberg release zip | Plug-and-play, no user-side Python/GPU |
| Audio playback | PlaySoundFile() with deterministic path | File exists → play, missing → silent fallback |
| Audio stop | CVar toggle hack (MasterSoundEffects) | No StopSoundFile() in 1.12 |
| Race design | Data-driven from quest crawl | Only ~20-30 races actually give quests out of 300+ raw values |
| Books/objects | Narrator voice (single default) | No NPC-specific voice needed |
| Demon split | Dreadlord + Imp + Succubus (3 profiles) | Immersive quality; other demon subtypes fallback to Dreadlord |
| Voice uniqueness | Per-NPC seed from name hash | Same race, different NPCs sound distinct but related |
| Voice consistency | Voice anchor (.voice_anchor.wav) | First generated line anchors all subsequent lines |
| Voice post-processing | Per-profile DSP (65 profiles) | Donor voice for extreme F0 + fantasy effects for creature character |
| Voice anchor clean | Effects applied after anchor save | TTS gets undistorted reference; effects on final output only |
| Pitch correction | Donor voice + post-shift | Clean human samples for TTS; pitch shift output to target |
| Tier 3 voices | Direct custom samples, no seed variation | Named NPCs sound exactly like their reference clips |
| Tier 3 aliases | "Lord Tirion Fordring" → tirion_fordring | Quest ender name differs from NPC name; same custom voice |
| TTS language | Hardcoded English | Fish Speech `normalize=True` handles English text normalization |
| Sex data | DBC files (no re-crawl) | CreatureDisplayInfoExtra col 2 = DisplaySexID |
| Pre-crawl | Quest text + world objects/books | Instant voice for most interactions |
| Player markers | Raw in DB, substitute at TTS time | Generic substitution ("adventurer") for pre-generated |
| Marker format | `<name>`, `<class>`, `<race>`, `$G` | Website converts $N→<name>, $C→<class>, $R→<race> |
| Emote markers | Strip silently for TTS | Voice profile handles tone/character, not text cues |
| Gossip text | Curated manual entries only | Bulk gossip too repetitive; lore-significant gossips added manually with NPC voice |
| Emotion tags | Fish Speech inline `[tag]` via LLM | Ollama + glm-4.7-flash for free local tagging; 69-tag whitelist; cached to disk |
| Monster speech | Excluded | CHAT_MSG_MONSTER_SAY/YELL not worth covering |
| Quest log | Queue UI replaces dedicated replay buttons | `QuestLogButton.lua` not needed; queue frame + `/tt show` covers replay |
| Inventory-item quests | Manifest hash index fallback | `UnitName("npc")` returns nil for item-triggered QUEST_DETAIL; hash index bypasses NPC name |
| 3D portrait text layout | All text anchored to frame TOP center | PlayerModel 3D overflows bounds downward; anchoring below portrait causes overlap |

| Settings tables | Three separate SVars tables | basicRaceToggles / creatureToggles / customNPCToggles — priority ordering cleanly expressed |

- Cloud TTS (ElevenLabs, etc.) — local GPU only
